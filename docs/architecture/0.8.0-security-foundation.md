# 0.8.0 Security Foundation

This migration must be deployed together with the core schema before PRE is exposed to application traffic.

## What it adds

- same-tenant organization hierarchy enforcement
- team/category sport consistency
- organization sport enablement for teams
- membership/team organization consistency
- automatic `updated_at` triggers
- RLS helper functions
- RLS on every core table
- no anonymous direct table access
- conservative authenticated grants and policies

## Important design choice

`persons` is read-only from the browser during the foundation phase. Person creation and privileged updates will be mediated by server-side functions / Edge Functions after authorization. This avoids allowing a browser client to create arbitrary identities before the workflows are defined.

## PRE gate

Before merge into `develop`:

1. start local Supabase
2. run `supabase db reset`
3. run `supabase db lint --local --fail-on error`
4. only then merge to `develop`

No migration from 0.8.x is applied to PRO yet.
